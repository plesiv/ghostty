02 / Repository map

The lay of the land.

Start with the shared engine, then follow the platform app, public interfaces, examples and release infrastructure.

⌘/src

Shared engine & app core

The main Zig codebase: terminal emulation, renderer, fonts, configuration, input, CLI, OS abstractions and application runtime components.

◫/macos

Native macOS app

SwiftUI application, assets, entitlements, Xcode project, UI and unit tests—connected to the shared core.

▧/include · /src/lib_vt.zig

Public VT library surface

C headers and the Zig library implementation for libghostty-vt: reusable terminal parsing and state APIs, also targeting WebAssembly.

⌁/example

Runnable examples

Small C, C++, Zig, Swift and WebAssembly projects demonstrating VT streams, rendering, input encoding, selection and more.

✓/test

Tests & validation

Project test resources, fuzzing support for libghostty, platform test material and test workflows throughout the source tree.

▤/dist · /pkg

Build, package & ship

Distribution metadata and platform packaging alongside dependency recipes and build support for development and release outputs.

03 / Build & ecosystem

One build graph.
Many destinations.

The root Zig build coordinates the app, shared dependencies, resources and library artifacts. Platform-specific packaging and project files complement it.

Read the build entry point ↗
Build system

build.zig and build.zig.zon define Zig targets, build options, app outputs, tests and library builds.

Platform UI

macos/ contains the native SwiftUI app; Linux UI and runtime integration live under src/apprt/gtk/.

Interfaces

include/ghostty/ exposes public C headers; example/ shows how to consume the VT library from several languages.

Project care

po/ holds translation catalogs; dist/, pkg/, nix/ and flatpak/ support distribution and packaging.

Quality

.github/ contains workflow and contribution automation; tests, fuzzing and benchmarks help validate behavior and performance.
